# Find and open CORA products in public S3

- Bucket: `s3://noaa-nos-cora-pds/` in `us-east-1`. Start with NOAA's [bucket README](https://noaa-nos-cora-pds.s3.amazonaws.com/README), [metadata](https://noaa-nos-cora-pds.s3.amazonaws.com/metadata.txt), and Intake catalogs [for Zarr 2](https://noaa-nos-cora-pds.s3.amazonaws.com/CORA_intake.yml) or [for Zarr 3](https://noaa-nos-cora-pds.s3.amazonaws.com/CORA_intake_zarr3.yml). Choose the catalog matching the installed Zarr version. Use the catalog's source ID, exact key, and options to select the data. Some catalog descriptions repeat water-level text for wave sources. Check the variable and metadata.
- For products outside Intake or when a key fails, list the relevant `cora_gec/` or `cora_pac/` prefix using anonymous S3 (for example, `aws s3 ls --no-sign-request s3://noaa-nos-cora-pds/<prefix>/`). With S3 ListObjectsV2, use a narrow prefix and follow continuation tokens as needed. Do not build new paths under the old `V1.1/assimilated/` hierarchy. Confirm availability with an actual small data read as well as metadata.
- A `.zarr` key can be a single Kerchunk JSON object or a directory store. If the exact key is a JSON reference, use `fsspec.filesystem("reference", fo=key, target_protocol="s3", target_options={"anon": True}, remote_protocol="s3", remote_options={"anon": True})` with the S3 URI as `key`. With Zarr 2, open the reference mapper with `xarray.open_zarr(fs.get_mapper(""), consolidated=False, chunks=None)` for lazy indexing, or use native chunks with Dask when useful. With Zarr 3 use NOAA's catalog options, including async S3 options where specified. References can name backing objects as `noaa-nos-cora-pds/<key>` without a scheme. For a direct HTTPS range request, use `https://noaa-nos-cora-pds.s3.amazonaws.com/<key>`. Preserve exact offsets and lengths.
- For a directory store, use the anonymous S3 mapper and open with consolidated metadata when present. For a standalone NetCDF4 or HDF5 file, prefer the published reference if available. Otherwise open by byte range with a seekable anonymous S3 file and a compatible reader such as `h5netcdf` or `h5py`. Keep the underlying file open through the read. Inspect named groups or datasets before loading. For an ADCIRC text mesh, use embedded coordinates/connectivity first when they satisfy the request. If the text file itself is needed, check its size and stream the required mesh records.
- Choose the smallest matching reference for the period, such as an annual map or multi-year point-series shard. Prefer one time slice per full spatial chunk for maps and chunks with many times and few nodes for point series. Apply spatial indices before materializing data. If a validated reference cannot read its backing object, try another matching reference or the exact NetCDF object via range access. Avoid full-object downloads as a recovery strategy.
- Verify integer encoding from the raw storage dtype (for example, Kerchunk `.zarray` or xarray encoding with CF decoding disabled). Decoded xarray values may be floats even for an integer source. Native map and time-series references checked in both domains store `zeta` as signed 16-bit integer millimeters with Zarr fill `-9999`. Georgia shoreline Zarr uses `-32768`. Read the selected object's own fill and packing metadata. For water levels, convert valid millimeters to meters only if needed.
- NOAA's [datum notebook](https://github.com/NOAA-CO-OPS/CORA-Coastal-Ocean-Reanalysis-CORA/blob/main/CORA_Convert_Datums.ipynb) identifies CORA water levels as MSL. Some variables retain ADCIRC attribute text referring to the geoid. Use MSL for CORA water-level results and cite NOAA's documentation if that attribute text is relevant.
